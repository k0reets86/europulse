# EPV2 Semantic Enrichment And Media Contract

Дата: 2026-03-28
Статус: обязательный жёсткий контракт для всей автоматизации `v2.1`

## Базовый принцип

Автоматизация обязана работать строго по этой схеме и не имеет права смягчать логику:

1. собрать новый материал
2. отсеять мусор
3. провести первичную семантическую оценку
4. сохранить контекст материала
5. при слабом пакете выполнить обязательный допоиск и дообогащение
6. собрать сильную `DE` master-версию
7. подобрать релевантное source-first media
8. выполнить `UK` и `EN` переводы только после готовности master-пакета
9. пройти quality/release/google проверки по всем версиям
10. перевести в `Готов к публикации`
11. опубликовать

## Контекст

Контекст материала обязан сохраняться с момента первичной семантической оценки до подтверждённой публикации.

Контекст запрещено чистить:

- на `rebuild_bundle`
- на `publish_finish`
- на `retry_process`
- на `ready_publish`
- на любом ручном подтверждении

Контекст можно чистить только после подтверждённой публикации материала на сайте.

Обязательные поля контекста:

- главная тема
- событие
- участники
- организации
- локации
- даты
- цифры, суммы, цены
- ключевые тезисы
- ключевые формулировки
- альтернативные названия и синонимы
- язык первоисточника
- тип сюжета
- набор поисковых опор

## Правила семантического допоиска

Каждый новый материал обязан получить `semantic_context`.

Слабым считается материал, если выполнено хотя бы одно условие:

- `source_count < 2`
- `supporting_count < 1`
- `quality < 90`
- `release < 90`
- `google < 90`
- мало фактов
- мало сущностей
- нет нормального медиа
- есть warning про слабый текст
- есть warning про слабый dossier
- есть warning про category mismatch
- есть warning про media mismatch

Для каждого слабого материала обязателен `semantic_search_pack`.

`semantic_search_pack` обязан включать:

- точное название события
- тема + локация
- тема + участник
- тема + дата
- тема + организация
- тема + ключевая формулировка
- сущность + синонимы
- запрос на языке первоисточника
- запрос на немецком
- запрос на английском

Порядок поиска:

1. первоисточник
2. официальные источники по теме
3. крупные профильные СМИ
4. локальные релевантные СМИ по географии события
5. дополнительные релевантные источники
6. любые fallback-источники только в самом конце

## Правила дообогащения

Если материал слабый, его запрещено переводить и запрещено отправлять в `ready_publish`, пока не выполнено дообогащение.

Дообогащение обязано:

- найти минимум `2-3` дополнительных релевантных источника, если это возможно
- добрать факты
- добрать сущности
- добрать контекст
- добрать подтверждающие формулировки или цитаты
- добрать бэкграунд, если новость без него неполная

Доработка должна быть точечной:

- слабый текст -> чинить текст
- слабый контекст -> чинить контекст
- слабое медиа -> чинить медиа
- слабое SEO -> чинить SEO
- слабый перевод -> чинить перевод
- полный rebuild только если payload реально развален

## Правила медиа

Медиа подбирается по смыслу, а не по факту наличия картинки.

Приоритет медиа строго такой:

1. медиа из первоисточника
2. медиа из официального источника по теме
3. медиа из дополнительных релевантных статей по этой же теме
4. медиа из очень близкого источника по событию, локации или участнику
5. `Wikimedia` и `Pexels` только как крайний fallback

Медиа считается релевантным только если совпадает по:

- событию
- сущности
- локации
- времени
- типу сюжета

Медиа запрещено принимать, если:

- другая страна
- другой город
- другая организация
- абстрактный сток вместо события
- нерелевантный человек
- нерелевантное ведомство
- нерелевантное здание
- картинка подходит только "по настроению"

Если source-first media не найдено, автоматика обязана:

1. выполнить допоиск релевантных статей именно под медиа-задачу
2. извлечь медиа из этих статей
3. валидировать по контексту

Только после этого допускается fallback.

## Ручное подтверждение

Ручное подтверждение запрещено для обычных слабых новостей.

Сначала обязателен автоматический допоиск и дообогащение.

В `Требует ручного подтверждения` можно переводить только критичные кейсы:

- высокий риск нерелевантного медиа
- неоднозначная сущность
- конфликтующие источники
- нет безопасного автоматического способа подтвердить визуал

Если материал ушёл в `Требует ручного подтверждения`, он обязан:

- не показываться как `В работе`
- не участвовать дальше в автоматическом process-loop
- содержать явное объяснение:
- что не так
- что уже пробовали
- что именно нужно подтвердить

## Переходы по этапам

`Новый`:

- материал есть в живой очереди
- контекст сохранён
- слабый пакет отправляется в обязательное дообогащение

`В работе`:

- только один активный processing item
- только реально исполняемый этап
- нельзя показывать фальшивую активность

`Готов к публикации`:

- только при валидном media
- только после завершённого `DE` master
- только после завершённых `UK` и `EN`
- только после пройденных quality/release/google gates
- только если нет активных blockers

Если один материал уже в `Готов к публикации`, следующий `Новый` может идти в `В работу`.

## Анти-правила

Запрещено:

- чинить слабый материал только переводом
- чинить слабый материал только SEO
- закрывать отсутствие контекста стоковой картинкой
- отправлять в manual то, что решается допоиском
- пересобирать весь материал, если сломан один узел
- принимать `featured_media_url`, если URL есть, но медиа нерелевантно по смыслу
- чистить контекст до подтверждённой публикации
